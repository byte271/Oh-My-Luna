# Product thesis

## One sentence

Oh-My-Luna is a model-snapshot-specific repository capability runtime that
compiles issues into small source-addressed context and verified execution
steps, gives GPT-5.6 Luna only the high-level instruments a task needs, and
withholds completion when required evidence is missing or stale.

## What it is

- a local-first CLI and Codex plugin integration;
- a versioned Luna behavior/evaluation profile;
- a typed task, capability, evidence, trace, and receipt format;
- a small registry of deterministic primitives and validated macro
  capabilities;
- an evaluation product first and a runtime second.

## What it is not

- a claim that Luna becomes identical to Sol;
- a generic multi-agent framework or role marketplace;
- a prompt bundle that equates longer instructions with intelligence;
- an unrestricted source-code tool generator;
- a cloud service that silently receives private repositories;
- a proof that green tests equal user intent;
- a runtime with hidden Sol calls.

## Users and first tasks

Target users are individual maintainers and teams with many objectively
verifiable Python or TypeScript repository tasks where Luna's price is
attractive but repeated investigation mistakes erase the savings.

V0 task classes:

- GitHub issue to scoped bug-fix patch;
- CI failure and regression diagnosis;
- security-boundary defects with executable negative tests;
- cross-platform or runtime compatibility defects.

Windows, macOS, and Linux are control-plane targets. A sandbox backend must
attest its actual guarantees; unsupported generated-code execution is refused.

## Modes

- **Luna-only:** all runtime model calls use a pinned Luna snapshot. This is the
  default and the product's central evaluation subject.
- **Hybrid:** optional, visible escalation of a bounded decision to Sol with a
  separate cost line and receipt field. Never automatic by default.
- **Development teacher/evaluator:** Sol may create candidate fixtures, review
  traces, or propose policies offline. Its output is not accepted without
  deterministic or human validation and held-out Luna evaluation.

## Installation surface

The intended primary command is `oh-my-luna`. The Codex plugin supplies one
discoverable skill and, when justified, a local MCP capability server. Users do
not select roles. Developer commands may inspect profiles, validate fixtures,
and run experiments.

## Open-source and paid boundary

Open source must include schemas, local CLI/control plane, capability contracts,
local runner, evidence ledger, benchmark fixtures that can be redistributed,
scorers, security tests, and all release claims.

An optional paid product may provide hosted sandbox capacity, private benchmark
management, fleet analytics, or managed CI runners. It may not hide a stronger
runtime model while marketing Luna-only results, withhold the evidence needed
to reproduce public claims, or require uploading source for local use.

## Why choose it

- Over Luna alone: only if paired held-out runs show higher success or the same
  success at lower correction cost.
- Over Sol: only when Luna-only total cost is materially lower for a measured
  success target; Sol remains appropriate for model-bound work.
- Over Oh My Codex: a narrower Luna-specific, benchmark-owned capability and
  evidence system rather than a large general workflow/team layer.
- Over another coding agent: transparent attribution, full traces, explicit
  evidence validity, and no hidden model routing.

No unconditional “Sol-quality” claim is permitted.
