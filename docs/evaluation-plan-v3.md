# Evaluation plan V3

Status: pre-registered protocol; no capability result  
Supersedes: `evaluation-plan-v2.md`

## Gate M — method validation

Use four to six reviewed real task bundles to validate packet
boundaries, treatment-specific materialization, hidden-scorer blindness,
review records, frozen identities, randomization, repetition, receipts, cost
records, and deterministic failure handling. Gate M does not estimate Luna
performance. Synthetic fixtures must be labeled as mechanics-only.

## Gate H — causal headroom

Primary design: cumulative pre-edit ladder L0 native, L1 context, L2
localization, L3 observation, L4 diagnosis, L5 behavioral plan. Verification-gap
guidance is a separately timed, post-first-patch rescue treatment. Selected
independent arms may be pre-registered as secondary analyses; there is no full
factorial search.

Controls are native Luna, lean fixed Skill, equal-token Luna, equal-cost Luna,
and a same-harness Sol reference. Freeze snapshot, reasoning effort, task text,
workspace commit, visible tests, tool permissions, retries, token and cost
budgets, timeout, service tier, cache mode, prompts, Skill, environment, scorer,
task selection, packets, reviews, schedule seed, and all content hashes.

The primary output is the minimum sufficient intervention: the earliest level
that exceeds the pre-registered meaningful effect, respects payload/similarity
budgets, survives repository-disjoint held-out testing, and is not credibly
improved enough by later levels to justify their specificity. Track payload
tokens, regions, lines, symbols, facts, constraints, patch similarity, fixed-only
identifiers, and end-to-end outcomes.

Gate H permits claims about the value of correct information only. It does not
select or validate a component.

## Gate A — approximation feasibility

Freeze a new plan only after Gate H. Compare the smallest deterministic
baseline, a distinct training-free structured baseline when justified, one
learned component only after those baselines, the relevant oracle upper bound,
equal-token and equal-cost Luna, and Sol. Primary outcomes remain requested-
behavior and hidden-verifier task success, total cost per success, and fraction
of the observed Luna–Sol gap closed. Oracle fidelity, retrieval, calibration,
abstention, and harmful guidance are diagnostic.

A valid outcome is that the oracle category matters but no practical
approximation is justified.

## Selection and analysis

Freeze disjoint representative and high-gap slices before treatment runs. The
representative slice is not conditioned on model outcomes. High-gap inclusion
uses a pinned native failure rule and independent solvability evidence and is
reported as conditional. Never pool the slices into one headline result.

Task is the primary generalization unit. Report task- and repository-level
outcomes, independent task count, repeated trials, paired differences,
uncertainty intervals, cost, latency, harmful outcomes, treatment interactions,
and all attempts. Repetitions estimate stochasticity, not population size. A
12–20-task pilot is exploratory and cannot support a release claim.

## Cost integrity

Retain per-request standard, cached, cache-write, and output tokens; context
rules; tool fees; retries; specialist charges; service tier; provider records;
and an `actual`, `estimated`, or `not_applicable` label. Missing billing fields
remain explicit. Equal-token and equal-cost controls are separate arms.

## Current blocker

Four real tasks and their base/fixed mechanics exist. No live Luna adapter,
independent packet review, executable treatment freeze, or attested sandbox
exists. The current repository can validate mechanics only.
