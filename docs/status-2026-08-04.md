## 2. The path bug is not a Windows portability gap

`docs/gate-h-heldout-v2-plan.md` §6 records `new URL("../..", import.meta.url).pathname`
as a Windows-only defect, correct on the validated Linux platform. Half right.
`pathname` is **percent-encoded**:

```
$ node -e "console.log(new URL('../..','file:///home/user/Oh My Luna/scripts/x/y.mjs').pathname)"
/home/user/Oh%20My%20Luna/
```

`path.resolve` does not decode it, so a checkout under any path containing a
space, `#`, `?` or non-ASCII character fails on Linux too — with ENOENT on a
directory that visibly exists. The Windows behaviour is confirmed as well
(`win32.resolve("/C:/")` → `\C:`), so both failures are real; the recorded
characterization was just narrower than the defect.

Corrected in every script outside the freeze. The frozen scripts keep the bug by
necessity and the v2 replacements do not have it.

### 3b. The evaluator leaks a workspace copy per evaluation

`evaluate.mjs` puts its scratch cleanup in a `finally` and calls `process.exit()`
on every terminal path. `process.exit()` does not unwind, so the `finally` never
runs:

```
$ node -e 'try { console.log("try"); process.exit(17); } finally { console.log("finally"); }'
try
$ echo $?
17
```

One recursive copy of a repository workspace is abandoned in `tmpdir` per
evaluation — twenty per Stage A, and the injection-error path at `:70` cleans up
explicitly, which is what shows the omission is a slip rather than a design. The
v2 evaluator sets `process.exitCode` and returns, so its `finally` runs. Measured
across 100 v2 evaluations: zero directories left behind.

## 4. Two latent defects that the planned v2 change would have activated

Neither fires today. Both would have fired the moment §1 of the plan put source
into the prompt, and both are silent.

**Prompt corruption via `String.replace`.** v1 assembles prompts with
`.replace("{{ISSUE}}", issue)`. A string replacement expands `$&`, `` $` ``,
`$'`, `$1`–`$99` and `$$` **in the replacement**:

```
$ node -e "console.log('<a>{{ISSUE}}</a>'.replace('{{ISSUE}}', '\$\`'))"
<a><a></a>
```

No issue file in the corpus contains a `$`, so v1 is unaffected. Source code is
full of them — `.replace(/x/, '$1')` is ordinary in `scule`, a string-casing
library, and `${…}` appears in any template literal. The corrupted prompt would
then be hashed into `prompt_sha256` as though it were the intended text, and the
resulting failures would be attributed to the model.

**Second-pass injection.** Sequential `.replace()` calls rescan text introduced
by the previous call, so source containing the literal `{{ASSISTANCE}}` would
have assistance metadata spliced into it. v2 substitutes every placeholder in one
pass with a function replacer, which performs no `$` expansion and never
rescans.

## 5. Protocol v2 — implemented, gated, and deliberately not frozen

Plan steps 1–6 are done. Steps 7 and 8 are **not**, because step 7 is two owner
decisions and step 8 is the freeze that would consume them.

Implemented:

- **§1** Every arm, T0 included, receives the complete source of each permitted
  path at the base commit. The false line `Repository root contains the project
  source.` is deleted.
- **§2** Four sufficiency gates, offline and blocking:
  `prompt_completeness`, `output_cap_headroom`, `template_claim_audit`,
  `stub_realism`. v1 fails three of four; the v2 candidate passes all four.
- **§3a** The output cap is set from measurement, not assumption: 24,576, of
  which 16,384 clears the largest envelope (15,262) by 7% and 8,192 is reserved
  for reasoning tokens, which `max_output_tokens` bounds together with the answer.
- **§3b** Returned files are diffed against the base commit. `hunks_changed`,
  `lines_added`/`removed`, `changed_regions_outside_cited_regions`,
  `line_ending_changed` and `unrelated_edit_suspected` are recorded per attempt.
  **Diagnostic only.** Success remains exactly `evaluator_exit === 0`; the diff
  explains failures and never creates passes.
- **§6** `fileURLToPath` throughout.
- **§8's fixable half** A timeout is exit 18 and a foreign signal is exit 19,
  both distinct from a test failure at 17, and both marked
  `attributable_to_model: false`.

The output-cap decision is worth stating plainly, since it is a judgement call:
raising the cap was chosen over shrinking the corpus. Dropping the two oversized
tasks would take five tasks to three and remove both Python repositories, leaving
a single-language corpus. The cap costs about $0.02 per request at the
pessimistic reservation and changes no measurement. The alternative is recorded
with its rule in `tasks/gate-h-heldout-v2/protocol.candidate.json` in case the
owner prefers it.

### The stub rule is now enforced by a type, not a convention

The generalized lesson from the v1 defect was: **a stub must not be better
informed than the model it stands in for.** v1's `oracle` and `noop` both ran
`git show`, so a green 20/20 dry run coexisted with a protocol no model could
satisfy.

In v2 an unprivileged stub's signature is `(input: { prompt, permittedPaths }) =>
string`. There is no filesystem argument, so it cannot read one. `noop` therefore
reconstructs the base file **from the prompt**, which makes it a live sufficiency
test: under a v1-shaped prompt it cannot produce the file at all and the run goes
red. `oracle` remains privileged, declared as such, and its passes may never be
read as evidence that the prompt is adequate.

A fifth stub, `unseen`, returns a plausible hallucinated file — what a model
never shown the source actually does. It is the regression test for this defect.

`npm run heldout:v2:stubs` asserts each stub's expected outcome instead of
leaving it to an operator to eyeball:

```
PASS  oracle   20 attempts, $0.0000
PASS  noop     20 attempts, $0.0000
PASS  prose    20 attempts, $0.0000
PASS  unseen   20 attempts, $0.0000
PASS  mixed    20 attempts, $0.0000
```

`noop` passing its expectation carries the strongest single result here: it
requires **zero diff hunks on all 20 cells**, which means the v2 prompt
round-trips every corpus file byte-exactly.

## 6. Hardening in the change-set path

Four defects in the v1 validator, which is pinned by the freeze and could not be
corrected in place. The v2 validator is a separate module:

- **fail-open on an empty permitted set** — v1 guarded membership with
  `permitted.size > 0`, so a task with malformed `permitted_paths` accepted
  writes to any non-escaping path;
- **duplicate paths** silently collapsed to whichever was written last;
- **foreign-platform absolutes** (`C:\…`, `\\host\share`) not absolute under a
  Linux `isAbsolute`;
- **no containment check.** Stage A links the shared base worktree's
  `node_modules` into each workspace to skip a per-attempt install. A write
  through that link escapes the disposable workspace into state every later
  attempt reads. v2 resolves symlinks and refuses.

The evaluator subprocess also no longer inherits `OPENAI_API_KEY`. v1's
`evaluate.mjs` carries the comment "the evaluator gets no treatment identity and
no credential", which was true of its grandchild test runner and false of itself:
`run-stage-a.mjs:51` spawned it with the full `process.env`.

## 7. `provision.mjs` exit codes were unreachable

## 9. Position

The critical path is shorter than it was and still costs nothing. Steps 1–6 of
the v2 plan are implemented and their gates pass. What remains before a freeze is
not engineering:

1. **§5** — include the skill-control arm or not. Without it, a T1 gain is
   ambiguous between "the specific context helped" and "being told to work
   systematically helped." Cost: Stage A goes from 20 attempts to 25.
2. **§8** — whether `evaluator_exit === 0` is an adequate outcome measure, given
   that it cannot express asymptotic cost, adversarial robustness, or whether a
   self-reported verification step verified anything. Three options with their
   costs are in the plan.

Both are the owner's, and both become author discretion the moment results
exist. That is why v2 is a candidate file and the v2 runner refuses to spend
money.

The binding constraint has never been the credential. It is now these two
decisions.
